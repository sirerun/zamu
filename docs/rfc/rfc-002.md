# RFC 002: Extend Zamu for distributed voice backends

- Status: Draft proposal; not accepted in Zamu.
- Date: 2026-11-03
- Scope decision: The owner directed that voice orchestration extend Zamu while Homeward remains a separate, independently usable home-to-cloud dial-in component.
- This proposal belongs to Zamu and extends RFC 001. Homeward owns its separate transport RFC.

## Problem and decision

A voice host needs interruptible conversations using independently selectable speech recognition, language model, and speech synthesis backends. Zamu already owns voice-turn coordination, with Listener, Agent, Synthesizer, and Player interfaces. A second voice library with parallel interfaces and a translation layer into Zamu would duplicate cancellation, playback, and failure contracts.

Extend Zamu's existing interfaces and optional adapters where evidence shows a gap. Do not introduce a second conversation engine or a dependency from Zamu core on Homeward or Zati. Zamu remains directly usable by any Go host. Homeward is one optional transport for reaching home capabilities.

## Ownership

| Concern | Owner |
| --- | --- |
| Turn assembly, interruption, stable phrase emission, playback coordination | Zamu |
| Speech recognition implementation | MISTT or another selected provider |
| Speech synthesis implementation and model serving | Narrate or another selected provider |
| Backend adapters and host-configured selection | Optional Zamu packages |
| Persona, history, tools, consent, credentials, budgets and policy | Host application |
| Outbound connection, scoped API exposure and transport lifecycle | Homeward |
| Remote session controls | Existing Prosody boundary; do not duplicate it |

Homeward transports requests; it does not decide conversation turns, execute host tool policy, or acquire ownership of voice records. Credentials stay with the component that owns the provider or local service.

## Existing baseline and compatibility

The published source baseline used for this revision is [Zamu `65a6096`](https://github.com/sirerun/zamu/commit/65a609671fff1d63853484ee3f6c6e18d080c704) (main). The
existing optional adapters are `adapters/mistt`, `adapters/narrate`,
`adapters/native`, and `adapters/openrouter`. Remote recognition and synthesis
are already part of the architecture; distributed backends are not a new
coordinator. RFC 001 records landed source and local verification, with installed
runtime qualification still pending.

This proposal preserves RFC 001 unless an accepted amendment names the exact
contract being changed. In particular, recognition must retain admitted source
and stream identity, ordered capture offsets, finalized-through coverage and gap
handling. A backend without complete coverage cannot commit turns automatically.
Audio must preserve generation, sequence, offset, declared format and rendered
playback receipts. Capability declarations alone do not establish these guarantees.

## Proposed Zamu extensions

### Backend integration

Inventory existing adapters before adding new ones. Reuse Listener, Agent, Synthesizer, and Player, extending capabilities only where the existing contract cannot represent required streaming or cancellation behavior. Support local and remote backends without hardcoding topology into the coordinator. A Homeward adapter must be optional and translate transport failure into existing Zamu lifecycle semantics.

Model availability, audio formats, supported languages, streaming support, and cancellation behavior must be explicit capabilities. Unsupported combinations fail before opening capture or playback. Backend selection belongs to host configuration; provider credentials are not coordinator state.

### Interruption and conversational behavior

Preserve one authoritative turn coordinator. Every response and audio segment must remain attributable to its turn and generation. On confirmed interruption or explicit stop, cancel generation and synthesis, stop or flush playback, and reject late output from the cancelled generation. A remote cancellation acknowledgement is not evidence that audible playback stopped; qualify that at the player boundary.

Preserve RFC 001’s provisional pause and acknowledged-cursor resume for a qualified backchannel; it must not invalidate the generation or repeat rendered samples. Unknown classification or timeout invalidates instead of resuming. Backchannels and overlapping listening/playback already exist in the baseline. Evaluate additional speculative responses as bounded additions to that lifecycle. Speculation must not dispatch host tools or other effects before host authorization. The implementation must define which provisional outputs can be discarded and when a response becomes committed to history.

### Failover

Propose host-configured, ordered fallback among explicitly permitted providers. Do not silently move private audio or text to an unapproved provider. A failure after partial audible output requires a host-visible policy decision; do not replay an entire response automatically. Provider switches must preserve turn identity and cancel superseded work. This fallback policy remains a proposal pending Zamu acceptance.

Fallback must distinguish recognition, host response production, and synthesis.
A recognition switch opens a fresh stream and capture timeline; incomplete
coverage requires a repeat, never stitching uncertain transcripts into a turn.
Retrying response production must not readmit an existing `Turn.ID` or replay its
host effects. Host admission and effect reconciliation remain authoritative even
when a provider disconnects before any audio is heard. Cancellation of a response
stream neither cancels an admitted task nor proves stopped remote compute/billing.

A replacement output attempt retains the logical turn identity but uses a fresh
output generation, fencing all superseded text, PCM and acknowledgements. Before
fallback, the host must resolve uncertain playback progress or stop and report an
unknown outcome; absence of a receipt is not proof that no audio was heard.
Provider permissions include data destinations and budget. RFC 001's prohibition
on automatic paid speech fallback remains in force unless explicitly amended.

### Speech synthesis evaluation

Pocket TTS is a candidate through the synthesis owner, not a required dependency of Zamu or Homeward. Choose models using listening tests, target-language quality, streaming latency, interruption behavior, resource use and licensing checks. No model is selected by this RFC.

## Qualification

First establish the current Zamu baseline using its accepted RFC and tests. Then qualify each new behavior independently:

1. Existing local conversation works without Homeward installed or configured.
2. A remote backend works through an optional adapter using the same coordinator.
3. Interruption during generation, synthesis and playback suppresses late output.
4. Disconnect and slow consumption remain bounded; no stale audio plays after reconnect.
5. Provider fallback obeys host permissions and never duplicates a host effect.
6. Record first-audio latency, interruption-to-silence, turn completion, memory bounds and failure outcomes on named hardware and revisions.
7. Inject reordered and duplicate frames, stale generation receipts, missing recognition coverage, disconnect during uncertain host admission, and fallback after partial or unacknowledged playback. Verify rejection or explicit recovery with no readmission of host effects.
8. Specify adapter queue limits, operation deadlines and cleanup behavior before qualification. Exercise a stalled consumer and a cancellation-ignoring provider; demonstrate bounded retained work and explicit failure rather than silent replay.
9. Evaluate natural turn-taking with Full-Duplex-Bench or an equivalent documented suite, plus human listening. Benchmark selection and thresholds require acceptance; a benchmark score alone is not audible acceptance.

## Delivery and unresolved decisions

This document authorizes no runtime effects. Obtain owner acceptance of the extension scope and explicit API deltas in Zamu before implementation. Resolve API deltas from current source rather than copying the previous standalone-library API. The home transport proposal lives in [Homeward PR #1](https://github.com/zati-run/homeward/pull/1).

Open decisions are exact Zamu interface changes, fallback commit points, benchmark thresholds and synthesis model selection. The earlier D1–D12 discussion is historical input, not automatic acceptance of replacement contracts. The superseded standalone-library draft is preserved in Homeward Git history at c008285.

## Revision review

Review of the initial draft found and corrected the mistaken repository rename,
missing baseline/compatibility constraints, conflated pause/interruption behavior,
and underspecified fallback identity and uncertain outcomes. This is a documentation
revision only: it supplies no new runtime, provider or audible qualification.
